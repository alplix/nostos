# Nostos

**Nostos** (νόστος, "homecoming") is a volunteer-computing project, sharing [bitboinc](https://bitboinc.athena.org.tr)'s BOINC infrastructure, that searches for the **origin stars of interstellar objects** — asteroids and comets like 1I/'Oumuamua and 2I/Borisov that passed through the Solar System on hyperbolic trajectories, having come from somewhere else in the Milky Way.

## The idea

An interstellar object's current position and velocity, projected backward through the Galaxy's gravitational potential, traces a path through where it's been. Somewhere along that path, it may have had a close encounter with a star — close enough, long enough ago, to plausibly be where it was ejected from.

A handful of papers (most notably Bailer-Jones et al. for 'Oumuamua and Borisov) have done this kind of search, but against a hand-picked shortlist of candidate stars — a few dozen, chosen because they looked promising. Gaia's full catalog has tens of millions of stars with complete 6D phase-space data (position + velocity). Nobody has run the exhaustive version: every known interstellar object, against *every* Gaia star with full 6D data, with proper Monte Carlo propagation of each object's own orbital uncertainty. That's the computational gap this project fills — and it isn't a one-off: Rubin Observatory/LSST is expected to find many more interstellar objects in the coming years, so this is lasting infrastructure, not a single analysis.

## How it works (planned)

1. Each known interstellar object's orbital elements (public, from JPL Small-Body Database / Minor Planet Center) are resampled into many Monte Carlo realizations spanning its measurement uncertainty.
2. Gaia DR3's ~33 million full-6D-phase-space stars are split into chunks and distributed to volunteers as BOINC work units.
3. Each work unit integrates its chunk of Gaia stars *and* the interstellar object's Monte Carlo realizations backward through a standard Milky Way gravitational potential (no star-star N-body needed — each trajectory is independent in a smooth background potential), looking for closest-approach distance and time.
4. Close encounters below a threshold distance are reported back; everything else is discarded to keep result sizes small.
5. The pipeline is validated against the *already-published* candidate origin stars for 'Oumuamua and Borisov before being trusted on anything new — if it can't reproduce known results, it doesn't get to report new ones.

- [x] **Core integrator** — `src/integrator.h` (leapfrog) + `src/potential.c` written and validated against exact conservation laws and the analytic Kepler solution (`tests/test_kepler.c`, all passing). The Milky Way potential is now Allen & Santillan (1991)'s actual published model (Plummer bulge + Miyamoto-Nagai disk + a truncated generalized-enclosed-mass halo), replacing the earlier generic Hernquist+MN+NFW placeholder -- bulge and disk are cross-checked against `galpy` component by component (`tests/test_milkyway_galpy.c`, ~1.7e-6 relative error, in-plane and off-plane); the halo (no stock galpy equivalent) is validated via energy/acceleration self-consistency and continuity across its truncation radius (`tests/test_milkyway_allen_santillan.c`). Resulting rotation curve: 203-232 km/s across 1-30 kpc. `src/coords.c` (astrometry <-> Galactocentric phase space) and `src/orbital_elements.c` (ISO orbital elements -> Galactocentric starting state) are written and tested (`tests/test_coords.c`, `tests/test_orbital_elements.c`, all passing) and cross-checked end to end against a real JPL Horizons state vector for 1I/'Oumuamua (`tests/test_horizons_crosscheck.c`) -- position and velocity both match to ~1e-6 relative error, confirming the full rotation chain's direction/sign convention, not just internal self-consistency.
- [x] **Encounter search kernel** — `src/encounter.c`'s `find_closest_approach()` integrates a star and an ISO realization together and tracks their minimum separation. Validated against an exact analytic (GM=0, straight-line motion) case (`tests/test_encounter.c`, all passing). `src/montecarlo.c` (a seedable PRNG + Cholesky-based correlated Gaussian sampler, validated statistically in `tests/test_montecarlo.c`) and `src/mc_search.c` (the stage-1 Monte Carlo wrapper around the above -- 100 ISO clones per star, per Bailer-Jones et al. 2019's own number, deterministic per seed for BOINC quorum validation; `tests/test_mc_search.c`) implement the Monte Carlo scheme decided in `NOTES_method_selection.md`. Stage 2 (star-side resampling from Gaia's own errors and correlations) is `src/star_mc.c` (`tests/test_star_mc.c`), driven by `tools/mc_shortlist.c`.
- [x] **Pipeline validation** — tested against three real reference stars across two interstellar objects: HIP 3757 and HD 292249 for 'Oumuamua (`tests/test_pipeline_oumuamua_hip3757.c`, Bailer-Jones et al. 2018) and Ross 573 for Borisov (`tests/test_pipeline_borisov_ross573.c`, Bailer-Jones et al. 2020). The long-open "right order-of-magnitude speed, very wrong distance" discrepancy documented here for most of this project's history is now LARGELY RESOLVED, after ruling out several other hypotheses (potential choice, Monte-Carlo-vs-best-fit — see `tools/mc_vs_bestfit_ross573.c`) one by one: the real bug was evaluating the ISO's orbital elements at the OUTBOUND (post-perihelion) asymptote rather than the INBOUND one. The Milky-Way-only backward integration never re-simulates the Sun's own gravity, so starting from the outbound state silently carries the wrong post-deflection velocity DIRECTION (off by the orbit's full hyperbolic turning angle — 112.7° for 'Oumuamua, 34.7° for Borisov) all the way back through the Galaxy, while leaving the SPEED unaffected (both asymptotes share the same v_infinity) — exactly matching the "right speed, wrong distance" symptom every test kept showing. Fixed everywhere (`src/gaia_scan.c`, `src/main_nostos_boinc.cpp`, both pipeline tests, both velocity-covariance tools). Time and speed then matched the published values to within a few percent, but distance was still off by a residual ~1.4-15x. **Closed 2026-10-08**: the ISO's starting state (Keplerian state 9.08 yr / 3.0 yr before perihelion) had the right direction but was 2.3% / 3.8% too FAST (vis-viva converges only like 1/r) -- an along-track error of ~0.6-1.1 pc per Myr. Every call site now starts on the exact inbound asymptote (`orbital_elements_inbound_asymptote_gm()`) of JPL's barycentric 1600 elements with the total solar-system GM, which reproduces Bailer-Jones et al. 2018's own Table 1 asymptote for the same orbit solution to every printed digit. Distances: HIP 3757 1.169 -> 0.556 pc (published 0.599 [0.527, 0.669]), HD 292249 2.307 -> 1.673 (1.605 [1.377, 1.868]), Ross 573 1.062 -> 0.080 (0.068 [0.053, 0.091]); with the papers' own inputs (their orbit solution, DR2 parallax zero-point, 2000-surrogate MC) the medians come out 0.602, 1.646 and 0.086 pc. The tests now assert all of this. The remaining few-hundredths-of-a-pc differences are input/potential-model level (see `NOTES_method_selection.md`, "Residual distance gap"). **Every Gaia-catalog scan result produced before this fix is stale** (see the "Data" item below).
- [~] **BOINC app** — CPU worker app written (`src/main_nostos_boinc.cpp`): one work unit = one ISO against one chunk of Gaia stars, runs `mc_search_stage1()` per star, reports only encounters under the work unit's own distance threshold. **Rebuilt 2026-10-08 with the starting-state fix** (`scripts/build_boinc_linux.sh`: static Linux x86_64 in WSL against the same locally built BOINC 8.2.8 libs bitboinc-app uses for its local Linux builds; a real link bug -- missing `extern "C"` around the C headers -- was found and fixed on the way) and re-tested end to end on a real 6-star work unit: HIP 3757 0.626 pc (clone mean; nominal 0.621), HD 292249 1.71 pc, far stars correctly filtered, 2.6 s/star. `scripts/make_work_units.py` (data-preparation half of a future work generator) writes the barycentric 1600 'Oumuamua elements the app's exact-asymptote start needs, Bailer-Jones et al. 2018's 7c asymptotic-velocity covariance (rotated to Galactic axes by `tools/oumuamua_velocity_covariance.c`), and zero-point-corrected parallaxes; all pinned by `tests/test_make_work_units.py`. Not deployed, no work generator/validator, no server-side registration (deliberately: those are production decisions, not made without the user's own review). See `NOTES_method_selection.md`, "BOINC app rebuilt and re-tested".

## Why "Nostos"

The Odyssey's word for a hero's long journey home. Fitting for a project whose entire point is finding out where a wandering visitor from outside the Solar System actually came from.
